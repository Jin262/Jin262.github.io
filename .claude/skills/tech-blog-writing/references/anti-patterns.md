# 안티패턴

CP3 자체 점검과 CP4 검토에서 하나씩 확인한다. 발견하면 위치와 고치는 방법을 보고한다.
반례 샘플 번호는 [`docs/references/korean-tech-blog-analysis.md`](../../../../docs/references/korean-tech-blog-analysis.md) §5에 있다.

| # | 안티패턴 | 찾는 방법 | 고치는 방법 |
|---|---|---|---|
| AP1 | 버전과 환경 없는 벤치마크나 트러블슈팅 | 프런트매터 `env`가 없거나 버전 번호가 없다 | 버전과 환경을 프런트매터 `env`에 넣는다(P3) |
| AP2 | 출처, 추정 여부 없는 수치 | 숫자마다 "어디서 왔나"를 묻는다 | 출처를 붙이거나(시간에 따라 바뀌는 값은 확인 날짜도), 추정이라고 쓰거나, 뺀다 |
| AP3 | 실행하지 않은 튜토리얼 | 명령 뒤에 출력이 없다. 결과 표가 비어 있다 | 실제 출력을 넣는다. 없으면 `<!-- 근거 필요 -->` |
| AP4 | 해결안을 제안만 하고 적용 결과가 없음 | "~하면 된다"로 끝나고 적용 후 관측이 없다 | 적용 결과를 넣거나 "적용 전"이라고 밝힌다 |
| AP5 | 원인을 "조사 결과"로만 제시 | 원인 절에 문서 인용만 있고 재현이 없다 | 재현이나 단일 변수 실험을 넣거나 "추정"으로 바꾼다 |
| AP6 | 핵심 근거를 이미지로만 제시 | 로그, 출력, 설정이 스크린샷뿐이다 | 텍스트 코드 블록을 함께 둔다 |
| AP7 | 제목이 본문 근거보다 강함 | 제목과 description의 주장이 본문의 조건과 표본 범위를 넘는다 | 조건을 제목에 넣거나 주장을 약하게 한다 |
| AP8 | 측정 방식 없는 성과 수치 | "N% 개선"에 기준선과 측정법이 없다 | 측정법을 쓰거나 "체감", "자기 보고"로 밝힌다 |
| AP9 | AI 생성 내용을 검증 없이 게시 | 확인하지 못한 주장이 본문에서 확정처럼 쓰였다. 출력·수치가 첨부 자료나 실행 기록에 없다 | 확인하지 않은 주장은 그 자리에 표시하고, 근거 없는 출력은 지운다 |
| AP10 | 알려진 반론 누락, 결론 없이 끝남 | 대안이나 단점 언급이 없다. 마지막 절이 요약도 판단도 아니다 | 트레이드오프 절과 조건부 결론을 둔다 |
| AP11 | 일반론 서론 | 첫 문단이 "~를 운영하다 보면", "요즘 ~가 화제다" | 증상, 질문, 사실 한 줄로 바꾼다 |
| AP12 | 코드 식별자 오탈자, 복붙 오류 | 본문의 함수명·변수명·명령이 코드 블록과 다르다 | 코드 블록 기준으로 맞춘다 |
| AP13 | `latest` 태그, 버전 없는 설치 명령 | `:latest`, `pip install foo`, `npm i foo` | 버전을 고정한다 |
| AP14 | 기준 버전 없는 레시피 | 프런트매터에 `env`가 없다. 또는 본문에 "실행 환경" 줄을 따로 썼다 | 버전을 프런트매터 `env`에 넣고 본문의 실행 환경 줄은 지운다. 날짜는 넣지 않는다 |
| AP15 | 지어낸 근거 (AI 특유) | 사용자 자료와 세션 실행 기록에 없는 출력, 수치, 이슈 번호 | 지우고 `<!-- 근거 필요 -->`로 바꾼다 |
| AP16 | 확신 과잉 어휘 | "반드시", "항상", "완벽하게", "모든"이 근거 없이 쓰였다 | 조건을 붙이거나 약한 표현으로 바꾼다 |
| AP17 | 이 글의 선택을 일반 규칙처럼 씀 | 정의·규칙 문장("A는 B다", "~하지 않는다", "~해야 한다")이 이 글의 그림 표기·예제·코드에서만 성립하는데 범위 표시가 없다. CP 결정을 본문으로 옮긴 문장은 결정의 전제가 빠지지 않았는지 본다. 예제 값을 대입한 식(정답 0일 때의 미분)을 일반식처럼 쓰지 않았는지도 본다 | "이 글의 그림에서는", "이 예제는"처럼 범위를 붙이거나, 일반적으로 맞는 문장으로 바꾼다 |

AP15~AP17은 샘플 분석이 아니라 AI가 쓰는 글의 위험을 막으려고 추가했다.
